# Plans

Each team member adds one file here: `<Name>-Work-Plan.md`.

Once all plans are in, we write `Master-Plan.md` (architecture and who builds
what). Nobody starts building before the master plan is agreed.

Suggested sections, so the plans are easy to merge:

1. What I am building (challenge, goal)
2. Data I need (modalities, plants, dates, size)
3. Pipeline (steps, inputs, outputs)
4. Outputs (table columns, files) — use the keys `bed`, `plant`, `date`, `hour`
5. Experiments or analyses
6. App pages I will deliver
7. Schedule
8. Risks
9. Questions for the master plan

**[Master plan](Master-Plan.md)** (proposed 2026-11-14): who builds what, the
shared table contract, the schedule to the Sunday 12:00 PM deadline. Where it
differs from a work plan, the master plan wins.
